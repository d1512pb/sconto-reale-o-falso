## Despliegue y continuidad

La consulta pública usa GitHub Pages y una proyección JSON del mart. SQLite queda disponible para una futura API/base de datos. El prototipo Streamlit permite inspección local. El modelo se ejecuta en el ETL, no al consultar un precio. No se guardan las entradas del usuario.

El workflow mantiene la captura existente y añade dos etapas independientes: análisis/publicación del ZIP y despliegue de la web. Ambas usan el mismo ETL del notebook. Si fallan, permanece el último paquete/sitio válido y se muestra su antigüedad. La versión académica queda congelada; la operación diaria usa snapshots nuevos.

La comprobación de consistencia incluye PK/FK de SQLite, hashes, nulos, ausencia de imputación, separación de canales, exclusión de eventos futuros, coincidencia de reglas Python/JavaScript y prueba del prototipo Streamlit con datos reales.
